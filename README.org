#+TITLE: EVA — Extensible Voice Assistant
#+OPTIONS: toc:2

EVA is an open Android assistant built to turn conversation into action across
your phone, existing apps, and services. Its design centers on fast voice
interaction, user-owned configuration, replaceable model providers, and
integrations that can be added without rebuilding the app.

* Design philosophy

These principles guide development. They describe the intended product; the
implementation and its limits are documented in [[file:docs/architecture.md][Architecture]].

** Get things done with minimal friction

Summon EVA, say what you want, and let it act. Routine authorized actions should
require little interaction. Opening another app for manual completion is a
fallback. Remember grants and preferences, and ask a short question when the
intended action or target is genuinely ambiguous.

** Use the apps you already have

Prefer existing Android interfaces and app capabilities. Useful integration
should not depend on persuading every app developer to support EVA. Declarative
packages should connect existing interfaces without code changes to EVA or the
target app; native adapters cover operations that need code.

** Own the entire configuration

All EVA configuration should be declarative, composable, and persisted primarily
in readable flat files suited to version control. A single user-owned EVA
repository should restore every EVA setting: instructions, models, providers,
extensions, grants, and preferences. Users should be able to combine, edit,
track, fork, share, and move their configuration between devices.

Configuration screens are convenient editors for that configuration. Adding a
setting means making it participate in the same persistence and restore model.
Credentials need protected storage and portable references, not plaintext in a
shareable repository. Android's device-level permissions and account
authentication require their own provisioning; restoration must make those
requirements explicit rather than silently dropping settings.

** Keep voice fast and natural

Short responses, interruption, and reliable actions matter. Typed interaction
should access the same capabilities. Simple phone actions should take a direct
path without unnecessary intermediary agents. Model and voice providers should
be replaceable independently of what EVA can do.

** Let work outlive a call

EVA owns persistent conversation context and action history. Ending a voice
interaction should not inherently abandon an accepted task. Remote agents,
including Paseo instances, fit as capabilities of the same assistant; the
conversation should not be tied to one service or one connection.

** Be reliable without becoming obstructive

Report what actually happened. Opening a draft, sending a message, handing off
an action, and verifying completion are different outcomes. Validate and record
actions in executable code, retain their evidence, and avoid repeating an
uncertain action merely because a connection was lost.

** Keep a useful stock-Android baseline

Standard Android APIs should provide useful capabilities on their own. Optional
power-user integrations such as Shizuku can expand what EVA does. Their absence
should disable the operations that need them, not the entire assistant.

* Current implementation

The native Kotlin/Compose app includes typed conversation, WebRTC voice,
on-phone ChatGPT sign-in and an API-key alternative, an Android assistant
surface, persistent threads, Android action adapters, and importable extension
packages. Prompt instructions are editable YAML. Device verification varies by
feature; implementation is not a promise of universal app or device support.

Paseo and general MCP connectivity remain planned integrations. See
[[file:docs/architecture.md][Architecture]] for boundaries and current limitations and
[[file:docs/operations.md][Operations]] for checks and recorded device evidence.

* Your configuration repository

In *Settings → User configuration → Choose folder*, select a synced checkout.
EVA creates =eva.yaml= from your settings or restores the file already there.
Choose the same repository on another device to restore its configuration;
EVA lists any credentials, apps, or Android authorizations still needed.
Use =include= files to share a base and keep local overrides. See
[[file:docs/architecture.md][Architecture]] for the format, composition rules, and restore behavior.

* Development and installation

The Nix development environment provides JDK 17 and Android SDK 37:

#+begin_src sh
direnv exec . just --list
direnv exec . just check
direnv exec . just install
# Or: nix develop .#android --command just check
#+end_src

The debug APK is =app/build/outputs/apk/debug/app-debug.apk= and installs as
=com.colonelpanic.eva.debug=, alongside the production app.

Production artifacts: [[https://github.com/colonelpanic8/eva/releases][GitHub releases]].
The configured self-hosted F-Droid source is
=https://colonelpanic8.github.io/eva/fdroid/repo=; it is separate from F-Droid's
official catalog. See [[file:docs/operations.md][Operations]] for signing and publication.
