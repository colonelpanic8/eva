#+OPTIONS: toc:2

* Status

EVA is an open, extensible Android assistant project. The Kotlin/Compose app
connects to a development broker using the host's existing ChatGPT login.
Natural-language typed requests reach a model, which can select map search,
navigation, and message-draft capabilities from EVA's catalog. The phone validates
and journals actions before dispatch; message drafts are not direct SMS sends.
The local command parser remains a diagnostic/test harness.

Native realtime WebRTC voice is implemented as a separate conversation mode,
with microphone permission, listen-only negotiation, mute controls, audio focus,
and cleanup. Voice mode performs phone actions through the same catalog and
dispatcher as typed mode, verified end to end with synthetic speech on an
emulator. EVA signs in to a ChatGPT account
on the phone with a one-time device code, and both typed conversation and
realtime voice are then carried by that subscription; an OpenAI API key remains
available as the metered alternative. Either way no workstation is needed, and
the paired host bridge stays available. Microphone capture and speaker playout are verified on a physical
phone; acoustic quality and interruption behaviour are not yet measured.
An opt-in [[file:docs/native-voice-testing.md][native speech test]] verifies generated speech, live transcripts,
and decoded provider audio on the emulator.
Native subscription login covers typed conversation and voice. Remote pairing
to a broker is still not implemented.

Paseo, AppFunctions, capability-package import, and privileged extensions are not
integrated. A separate [[file:experiments/device-control/README.md][device-control experiment]] verified Shizuku-backed
screenshots, UI inspection, text replacement and touch on an Android 16 emulator.
The [[file:experiments/voice-poc/README.md][browser voice POC]] remains the regression harness for subscription-backed
speech and counter tools through the host-side Codex process.

The proposed product direction and acceptance scenarios live in
[[file:docs/design.md][docs/design.md]]. That document is an outline, not a description of working
features.

The proposed component boundaries, provider and capability interfaces, extension
contracts, and implementation sequence live in
[[file:docs/architecture.md][docs/architecture.md]]. Voice feasibility experiments are tracked separately in
[[file:docs/proof-of-concept.md][docs/proof-of-concept.md]].

The [[file:docs/device-control-extension.md][device-control extension design]] uses the same general package and capability
API, with Shizuku behind versioned native operations and shared result artifacts.

Implemented boundaries, limitations, and the plan for adapting the merged voice
POC are recorded in [[file:docs/implementation.md][docs/implementation.md]].

* Foundation

- Package/application ID: =com.colonelpanic.eva=
- AGP 9.4.0 built-in Kotlin with Compose compiler 2.4.20
- Gradle 9.7.1 and stable Compose BOM 2026.09.00
- compile/target SDK 37, minimum SDK 23, JDK 17
- Stock Android APIs and documented intents are the intended useful baseline
- Paseo is the first planned substantial remote adapter
- OkHttp carries broker control; WebRTC carries native audio directly to the provider
- Privileged-extension libraries remain absent

* Development

The checked-in Nix flake supplies JDK 17 and Android SDK 37. Enter it through
direnv or explicitly:

#+begin_src sh
direnv allow
# Or without a direnv hook:
direnv exec . just check
# Equivalent direct shell:
nix develop .#android --command just check
#+end_src

Useful commands:

#+begin_src sh
just format        # apply Kotlin formatting
just check         # format check, lint, tests, debug APK
just icons         # regenerate app, F-Droid, and Paseo icons from the source SVG
just build         # debug APK only
just install       # adb-install the debug APK
#+end_src

The debug APK is =app/build/outputs/apk/debug/app-debug.apk= and installs as
=com.colonelpanic.eva.debug=, allowing it to coexist with a production build.

* Installation

From a checkout after a debug build:

#+begin_src sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
#+end_src

Once the external repository and first release exist, production APKs are
expected at:

- https://github.com/colonelpanic8/eva/releases/latest
- =https://colonelpanic8.github.io/eva/fdroid/repo= for the self-hosted F-Droid source

The latter is an independently published binary repository; it does not mean
EVA has been accepted into F-Droid's official catalog. See
[[file:docs/fdroid.md][docs/fdroid.md]].

* Release operations

Release builds fail closed unless all signing inputs are present. Version codes
are derived from semantic versions as =major * 1,000,000 + minor * 1,000 + patch=.
See [[file:docs/release.md][docs/release.md]] for the release procedure and
[[file:docs/external-setup.md][docs/external-setup.md]] for the one-time GitHub and signing setup that has
not been performed by this scaffold.
